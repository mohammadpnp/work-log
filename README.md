# ردپا 🐾

دفتر شخصی فعالیت‌های گیت، با Go، SQLite و یک رابط فارسی محلی. دو بخش اصلی: **کامیت‌های منتظر توضیح** و **گزارش کارهای دارای توضیح**.

## اجرا

نیازمندی‌ها: Go نسخهٔ 1.22 یا بالاتر، Git و GCC (برای درایور SQLite).

```sh
cd /home/pars2/go/worklog
go run .
```

داشبورد: http://127.0.0.1:7331

## نصب روی اوبونتو

```sh
./install.sh
```

باینری در `~/.local/bin/worklog` نصب می‌شود و سرویس **کاربر فعلی** پس از ورود به دسکتاپ اجرا می‌شود. نیازی به sudo نیست. اگر پورت 7331 با نسخهٔ دستی اشغال شده، ابتدا اجرای دستی را ببند.

```sh
systemctl --user status worklog
systemctl --user stop worklog
journalctl --user -u worklog
```

پس از نصب، در داشبورد **فعال کردن ثبت خودکار** را بزن. در **پروژه‌های من** یک پروژه اضافه کن یا مثلاً `~/Document` را جست‌وجو کن تا کامیت‌های خودت در ۹۰ روز گذشته وارد شوند. نسخهٔ اول ایمیل نویسندهٔ کامیت را با `git config user.email` هر پروژه تطبیق می‌دهد؛ برای ایمیل‌های قدیمی متفاوت، واردسازی خودکار انجام نمی‌شود.

## ثبت و گزارش

- کامیت جدید بعد از موفقیت گیت، در SQLite ثبت می‌شود؛ مرورگر و سرور لازم نیست باز باشند.
- در «منتظر توضیح»، روی **نوشتن توضیح** کلیک کن. پیام اصلی کامیت هم نمایش داده می‌شود.
- با ذخیرهٔ توضیح، کامیت به «گزارش کارها» می‌رود؛ توضیح خالی آن را به صندوق برمی‌گرداند.
- گزارش‌های امروز، این هفته (شروع شنبه)، این ماه **شمسی**، همهٔ زمان‌ها و بازهٔ دلخواه، با فیلتر پروژه و خروجی Markdown در دسترس‌اند.
- گزارش‌ها چهار نمای کارت‌ها، کانبان با ستون‌های پروژه‌ها، جدول فشردهٔ ۱۰ کار در هر صفحه، و «فقط توضیحات» دارند. نمای آخر متن کامل یادداشت‌ها را با لیبل رنگی نام پروژه در بالای سمت راست هر توضیح نمایش می‌دهد. در جدول، دکمهٔ ویرایش متن کامل توضیح را باز می‌کند؛ فیلترها و خروجی در همهٔ نماها یکسان‌اند.
- تاریخ‌های ورودی بازهٔ دلخواه میلادی هستند؛ نمایش تاریخ شمسی و منطقهٔ زمانی تهران است.
- صفحه هر ۱۵ ثانیه به‌روز می‌شود؛ هنگام نوشتن یادداشت، فرم دست‌نخورده می‌ماند.

## داده‌ها و هوک‌ها

دیتابیس و تنظیمات در `~/.config/worklog/` ذخیره می‌شوند (یا `$XDG_CONFIG_HOME/worklog`). یادداشت‌ها داخل مخزن گیت نوشته یا به سرویس خارجی ارسال نمی‌شوند. سرور فقط روی `127.0.0.1` گوش می‌دهد و درخواست‌های وب از مبدأ دیگر را رد می‌کند. دسترسی فایل دیتابیس فقط برای کاربر فعلی است.

نصب هوک، تنظیم قبلی `core.hooksPath` را نگه می‌دارد و هوک‌های قبلی را با آرگومان‌ها، ورودی و کد خروجشان اجرا می‌کند. برای پروژه‌هایی که مسیر هوک اختصاصی دارند، اضافه‌کردن پروژه از داشبورد، هوک‌های `post-commit`، `post-rewrite` و `post-merge` را متصل می‌کند و نسخهٔ اصلی را با پسوند `.worklog-original` حفظ می‌کند. اگر مدیر هوک پروژه این فایل‌ها را بازنویسی کند، پروژه باید دوباره متصل/بررسی شود؛ برنامه هوک تغییرکرده یا پشتیبان موجود را خودکار جایگزین نمی‌کند.

`amend` و `rebase` معمولی از `post-rewrite` برای انتقال یادداشت به شناسهٔ جدید استفاده می‌کنند. اجرای `--no-post-rewrite` یا ابزارهایی که هوک گیت را اجرا نمی‌کنند، این انتقال را دور می‌زند. ایمپورت دوباره، کامیت‌های با شناسهٔ یکسان را تکرار نمی‌کند. این برنامه زمان صرف‌شده روی کار را از تعداد کامیت تخمین نمی‌زند.

برای غیرفعال کردن، از دکمهٔ داشبورد یا باینری نصب‌شده استفاده کن:

```sh
~/.local/bin/worklog uninstall-hooks
systemctl --user disable --now worklog
```

غیرفعال کردن، تنظیم قبلی و هوک‌های اصلیِ دست‌نخورده را برمی‌گرداند و دیتابیس را نگه می‌دارد. قبل از حذف پوشهٔ داده، هوک‌ها را غیرفعال کن.

برای بکاپ سازگار از دیتابیسِ در حال استفاده، از قابلیت backup ابزار SQLite استفاده کن؛ کپی‌کردن تنها فایل `.db` هنگام فعال بودن WAL ممکن است همهٔ داده‌ها را شامل نشود.

## ساختار

```text
main.go       سرور محلی و API
store.go      SQLite و یادداشت‌ها
git.go        خواندن گیت و اتصال هوک‌ها
web/          HTML، CSS، JavaScript و گربهٔ متحرک
install.sh    نصب باینری و سرویس کاربر
```
